# 🛒 Shopping List Bot + API

Production-ready решение на **Node.js 20+ (ESM)**: Telegram-бот для совместных списков покупок и REST API
поверх одной и той же бизнес-логики.

## Стек

| Слой | Технология |
| --- | --- |
| Runtime | Node.js ≥ 20.12, только ESM (`"type": "module"`), `.env` через `process.loadEnvFile()` |
| Бот | `telegraf` v4 (long polling) |
| API | `express` v5 (`body-parser` не используется — `express.json()` встроен) |
| Валидация | `zod` v4 (`z.object` + `.safeParse`) |
| FSM | собственный менеджер состояний на `Map` с ключом `chatId:userId` |
| Хранение | in-memory (`Map`) + опциональный `data.json` через `fs/promises` |
| Тесты | `vitest` + `@vitest/coverage-v8` + `supertest` |
| Линт | ESLint 9, flat config (`eslint.config.js`), отступ 2 пробела |

## Архитектура

```
src/
├── index.js                  # bootstrap: загрузка .env → state → API + бот, graceful shutdown
├── config.js                 # единственное место чтения process.env (без dotenv)
├── api/
│   ├── server.js             # createApp(): express.json, /health, роуты, 404 + error handler
│   └── routes/lists.js       # POST /api/lists, GET /api/lists/:id (Zod-валидация)
├── bot/
│   ├── index.js              # createBot(): Telegraf + регистрация хендлеров + bot.catch
│   ├── fsm.js                # менеджер состояний: Map<`chatId:userId`, { step, data }>
│   ├── ui.js                 # рендер текста списка и inline-клавиатур (с escapeHtml)
│   └── handlers/
│       ├── commands.js       # /start /help /new_list /join_list /items /cancel
│       ├── actions.js        # callback_query: add / toggle / refresh / cancel
│       └── text.js           # шаги FSM: название → количество
├── services/
│   ├── listService.js        # ОБЩАЯ бизнес-логика для бота и API (единственный источник правды)
│   └── errors.js             # DomainError + коды ошибок (LIST_NOT_FOUND, ITEM_NOT_FOUND, ...)
├── storage/
│   ├── store.js              # in-memory state: lists, codeIndex, userList + resetState()
│   └── persistence.js        # опциональное сохранение/чтение data.json (fs/promises)
├── validators/schemas.js     # все Zod-схемы + formatZodError()
└── utils/id.js               # nanoid: код приглашения (6) и id покупки (10)
tests/                        # 69 тестов: unit + integration (API через supertest)
```

Ключевые решения:

- **Одна бизнес-логика на два входа.** Бот и API вызывают только функции `listService`, поэтому правила
  (уникальность кода, участие создателя, валидация количества) не дублируются.
- **FSM изолирован по `chatId:userId`.** Пользователи не «перетирают» состояния друг друга; ключ списка
  хранится в `data` состояния, поэтому диалог не ломается при переключении списков. При рестарте состояние
  сбрасывается — это допустимо по условию.
- **Ошибки не роняют процессы.** Доменные ошибки (`DomainError`) превращаются в понятные сообщения бота или
  в HTTP 400/404; всё остальное перехватывает `bot.catch` и Express error handler.
- **Токен только из окружения.** В коде нет ни одного хардкода токена, `.env` в `.gitignore`.

## Быстрый старт

```bash
# 1. Зависимости
npm install

# 2. Переменные окружения
copy .env.example .env      # Windows
# cp .env.example .env      # macOS/Linux

# 3. Заполните BOT_TOKEN (получить у @BotFather) в .env

# 4. Запуск API + бота
npm start
```

Что произойдёт:

```
[api] сервер запущен: http://localhost:3000
[bot] запущен в режиме long polling
```

Если `BOT_TOKEN` не задан — бот не запускается, API продолжает работать:

```
[bot] BOT_TOKEN не задан — бот отключён, доступен только API
```

Переменные окружения (`.env`):

| Переменная | Обязательна | Описание |
| --- | --- | --- |
| `BOT_TOKEN` | для бота | токен Telegram-бота |
| `PORT` | нет (по умолчанию `3000`) | порт HTTP API |
| `NODE_ENV` | нет | `development` / `production` / `test` |
| `DATA_FILE` | нет | путь к `data.json` для сохранения состояния между перезапусками |

## Команды бота

| Команда | Действие |
| --- | --- |
| `/start` | приветствие и список команд |
| `/new_list` | создаёт список, генерирует уникальный код, создатель становится участником |
| `/join_list <code>` | подключает к списку по коду, показывает участников; при неверном коде — сообщение об ошибке |
| `/items` | показывает участников и покупки со статусами + inline-кнопки |
| `/cancel` | прерывает текущий FSM-диалог |
| `/help` | справка |

Inline-кнопки: `➕ Добавить покупку`, `🔄 Обновить`, `✅/⬜️ <название>` — переключение статуса, `✖️ Отмена`
на шаге диалога. На каждый `callback_query` вызывается `answerCbQuery()` (убирает «часики»).

## API

### `POST /api/lists` — создать список → `201 Created`

```bash
curl -X POST http://localhost:3000/api/lists \
  -H "Content-Type: application/json" \
  -d '{"name":"Пятница","owner":{"id":"42","name":"Тест"}}'
```

```json
{ "id": "02ad6d5c-1570-4db3-946d-f62206b3f2be", "code": "YVEBVA", "name": "Пятница" }
```

Тело запроса опционально (`name` и `owner` не обязательны) — без тела создаётся «Список покупок».

### `GET /api/lists/:id` — состояние списка → `200 OK`

```json
{
  "id": "02ad6d5c-1570-4db3-946d-f62206b3f2be",
  "code": "YVEBVA",
  "name": "Пятница",
  "participants": [{ "id": "42", "name": "Тест" }],
  "items": [{ "id": "k3m9xq1a7z", "name": "Молоко", "qty": 2, "done": false }]
}
```

`GET /health` → `{ "status": "ok", "uptime": 12.3 }`

### Ошибки

| Код | Когда | Ответ |
| --- | --- | --- |
| `400` | тело/параметр не прошли Zod, битый JSON | `{ "error": "ValidationError", "details": [{ "path": "name", "message": "..." }] }` |
| `404` | списка нет / неизвестный маршрут | `{ "error": "NotFound", "message": "Список не найден" }` |
| `500` | непредвиденная ошибка | `{ "error": "InternalServerError", "message": "Внутренняя ошибка сервера" }` |

`POST /api/lists` с `{"name":"   "}`:

```json
{ "error": "ValidationError", "details": [{ "path": "name", "message": "Название не может быть пустым" }] }
```

## Безопасность

- Токен бота и порт берутся только из `.env`; в репозитории лежит лишь `.env.example`.
- `.env`, `data.json`, `coverage/`, `node_modules/` в `.gitignore`.
- Все внешние данные (тело запроса, path-параметр, тексты бота) проходят Zod-валидацию до бизнес-логики.
- Имена пользователей экранируются (`escapeHtml`) перед вставкой в HTML-сообщения.
- Тело запроса ограничено (`express.json({ limit: '64kb' })`), заголовок `X-Powered-By` отключён.
- Истёкшие `callback_query` и недоступные для редактирования сообщения обрабатываются без падения.
